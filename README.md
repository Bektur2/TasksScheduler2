Запуск:

mac / linux:

python3 -m venv venv
source venv/bin/activate
python3 -m pip install -r requirements.txt
python3 main.py

windows:

python -m venv venv
venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py





Решения: 

1) для хранения задач использовал sqlite

2) время от клиента принимается в его часовом поясе и сохраняется в utc

3) при выводе время переводится обратно в часовой пояс задачи

4) диспетчер раз в 3 секунды проверяет, какие задачи нужно запустить или завершить

5) для запуска задачи статус меняется с pending на running

6) captcha повторяется с задержкой, максимум 3 раза

7) при proxy_dead используется следующий прокси из списка

8) если попытки закончились, задача получает статус error и сохраняется причина




-Два раза подряд запустили цикл - как гарантируешь, что задача не стартует дважды?

Ответ: Перед запуском выполняется обновление статуса только для задачи со статусом pending.

если первый цикл уже поменял статус на running, второй цикл уже не сможет сделать это повторно.

после запроса проверяется количество изменённых строк. задача запускается только если была изменена одна строка


-Где слабое место, если задач станет много?
Ответ: слабое место sqlite и постоянный опрос базы каждые 3 секунды.

чем больше задач, тем больше строк приходится проверять, а sqlite плохо подходит для большого количества параллельных записей.

при росте нагрузки лучше перейти на postgresql, добавить индексы по статусу и времени и использовать очередь задач
